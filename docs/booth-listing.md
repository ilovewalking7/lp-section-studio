## 配布物の構成

```
lp-section-studio-v1.0.0.zip                     9.6 MB / 4555 ファイル
├─ README.md              使い方・導入手順（docs/dist-README.md が原本）
├─ LICENSE                ライセンス条文（リポジトリ root の LICENSE が原本）
├─ components/            React/TypeScript ソース 901件
│   ├─ demos/             880件（これが商品本体）
│   ├─ ui/                5件   Button / Card / Badge / Input / Switch
│   ├─ lib/               2件   cn() と i18n
│   ├─ registry/          12件  DemoMeta 型と i18n
│   └─ theme/             2件   tailwind.config.js と tokens.css
├─ html/                  静的HTML 880件 + index.json（standalone 判定つき）
├─ registry/              shadcn 互換 JSON 885件
├─ mcp/                   MCPサーバ（全部入り版 880件・LICENSE 同梱）
└─ studio/                ビルド済みスタジオ
```

`components/` が 880 でなく 901 なのは、demos の 880 件が
`@/components/ui/*`・`@/lib/utils`・`@/registry`（型）を参照するため。
これらを入れないと買った側でコンパイルが通らない。`theme/` は
`bg-card` などのトークン定義で、これが無いと色が出ない。

生成手順:

```bash
npm run html                    # 静的HTML 880件 → public/html/
npm run build                   # スタジオ + shadcn配信JSON（registry を内包）
node scripts/build-release.mjs  # 上を集めて ZIP 化（MCP全部入り版もここで作る）
node scripts/verify-release.mjs # ZIPを展開して件数・混入・実描画を検査
```

`build-release.mjs` がやっていること（手でやると間違えるところ）:

- `build-mcp-bundle.mjs --all` は出力先が `mcp/data/components.json` 固定で、
  リポジトリの無料版データを上書きしてしまう。退避 → 生成 → 復元している。
- 静的HTML と MCP が返す HTML に、Tailwind のトークン設定が入っているかを検める。
  素の `cdn.tailwindcss.com` には `bg-card` 等が無く、**880件中430件**がこれを
  使っているため、入っていないとその分の色が一切出ない。埋め込み自体は書き出しの
  源流（`src/lib/vanilla.ts` + `scripts/build-vanilla-head.mjs`）が行うので、
  ここでは足さずに検査だけする（同じ内容を2箇所に持たないため）。
- Vite が `public/` を丸ごと `dist/` に写すので、そのままだと `studio/` の中に
  `registry/` と `html/` が二重で入る（12MB の無駄）。除外している。
- `node_modules` / `.git` / `.env` / `crawler/` などを混入させない。

## ライセンス条文

**正本はリポジトリ root の [`LICENSE`](../LICENSE)。** ここに転記はしない
（二重管理になると、直したつもりの片方だけが配布されるため）。
`build-release.mjs` がそのファイルを ZIP の `LICENSE` と `mcp/LICENSE` に入れる。

弁護士レビューは行わない方針のため、Tailwind UI や Aceternity が公開している
商用ライセンスと同型の、実務で一般的な条項に留める。特殊な条項は入れない。

この手順書に元々書いてあった草案からの変更点は次の3つ:

1. **無料版の条項を足した。** 草案は「購入者は…」しか書いておらず、MCP 経由で
   配る無料版100個の扱いが読み取れなかった。`src/pages/Pricing.tsx` の FAQ は
   「無料版は個人利用・非商用の範囲」と明記しているので、条文にも入れた。
   無料版と買い切り版で条件が違う以上、どちらの版の話かが読んで分かる必要がある。
2. **英訳を用意した。** 草案は「（同内容の英訳。公開前に用意する）」という
   プレースホルダのままだった。日本語版を正文とし、相違があれば日本語が優先する
   旨を末尾に入れてある。
3. **第三者ソフトウェアの節を足した。** react / lucide-react / clsx /
   tailwind-merge / class-variance-authority / Tailwind CSS は本製品に含まれず、
   それぞれの MIT ライセンスが適用される、という当たり前の確認。

【保証】は草案では買い切り版の条項の途中にあったが、無料版にも当然かかるので
両方に適用される共通節として末尾に置いた。文面は変えていない。

### 「109件」について

いま4つの検査はすべて 0 件なので、109 という数字は再実行では出せない。
さらに note 記事に載せている内訳は、そのままでは 109 にならない。

```
コントラスト 12 + axe 29 + キーボード 0 + 横スクロール 26 = 67
```

記事本文は「axe が button-name 違反を29箇所」とも書いていて、
「29コンポーネント」と「29箇所」のどちらなのかで数え方が変わる。
109 は違反ノード数、67 はコンポーネント数、という可能性が高いが、
当時のログが残っていないため確認できない。**公開前に、どちらの数え方で
109 なのかを本人が確定させ、記事と商品説明の両方を揃えること。**
読み手が引き算できてしまう場所なので、合わない数字は信用を落とす。
